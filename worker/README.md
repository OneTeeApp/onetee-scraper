# `worker/` — the read API (Cloudflare Worker)

A small always-on program at Cloudflare's edge that reads the D1 database and
answers the website's requests. This is the *only* thing golfers' browsers talk
to; they never touch the scrapers or the database directly.

**Live:** `https://onetee-api.damp-snow-8025.workers.dev`
**Deploy:** `cd worker && npx wrangler deploy` (or the `deploy-worker.yml` workflow,
which needs the `CLOUDFLARE_DEPLOY_TOKEN` secret).

## Files

| File | What it is |
|---|---|
| `index.js` | The Worker itself (routes, freshness guard, prune cron). |
| `wrangler.toml` | Config: D1 binding (`env.DB` → `onetee-teetimes`) and the `[triggers]` cron. |
| `directory.gen.js` | Generated by `build_directory.py`; the bundled full course directory `/api/directory` serves. |
| `revalidate-ids.gen.js` | Generated `venue_id → platform IDs` map for `/api/revalidate` (plain platforms only). |

(`../worker-cpsprobe/` is a separate one-off probe Worker — not the live API.)

## Routes

| Route | Returns |
|---|---|
| `/api/health` | total / active row counts (is the DB alive?) |
| `/api/tee-times?state=&date=&city=&course=&platform=&max_price=&min_spots=&limit=` | individual open slots (the main golfer query) |
| `/api/courses?state=` | one row per physical venue (deduped by `venue_id`) |
| `/api/directory?state=` | every known course incl. phone-only/private (from the bundle, not D1) |
| `/api/revalidate` | live click-time re-check of one course (plain platforms only; others answer `"unknown"`) |

All D1 reads are parameterized SQL against `tee_times`, filtered to `active = 1`,
future-time, and the freshness guard.

## The freshness guard (the important bit)

`freshnessFilter()` adds a `NOT EXISTS` sub-select against the `sheet_freshness`
ledger: a slot is hidden unless its `(course_slug, date)` was re-confirmed within a
grace window that widens for further-out dates —

| date horizon | grace |
|---|---|
| day 0 (today) | 3h |
| days 1–2 | 6h |
| days 3–7 | 18h |
| days 8–30 | 30h |

So when a scraper stalls, its rows stay in the table but **silently drop off the
live site** rather than showing availability that might be wrong. A *missing*
freshness row means "never scraped since this shipped" and is **shown** — the guard
only hides on *proven* staleness (cold-start safe). Grace windows are tuned to be
≥ each horizon's slowest healthy re-scrape interval; the comments in `index.js`
record the incidents where too-tight windows hid real slots.

## Elapsed-slot pruning

`wrangler.toml` `[triggers] crons = ["*/5 * * * *"]` fires `scheduled()` every 5
minutes, which `UPDATE tee_times SET active = 0` for slots whose start time has
passed, grouped per state timezone (with a carve-out so the Central-time FL
panhandle isn't pruned an hour early). Runs on Cloudflare, not GitHub Actions,
because Actions' scheduler fired hours late. The read filter already hides elapsed
slots — this keeps the underlying data honest for any other consumer.

## Data model it reads

See `schema.sql`. Key tables: `tee_times` (the slots), `sheet_freshness` (the
freshness ledger the guard checks), `runs` (scrape audit log). The Worker also
joins a `venue_geo` table (`venue_id → lat/lng`) created outside `schema.sql`.

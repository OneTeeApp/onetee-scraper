# Codebase Map — what every part of the repo is

A guided tour of the whole repository. Skim the tree, then read the section for
whatever you're touching. One-liners only; open the file's own docstring for detail.

```
onetee-scraper/
├── README.md                     ← start here (the front door)
├── docs/                         ← the guides you're reading
├── *_golf_courses_booking.csv    ← human-edited source lists, one per state
├── build_registry.py             ← CSVs → registry.json (scrapable courses)
├── build_directory.py            ← CSVs → directory.json (ALL courses)
├── build_demo.py                 ← tee-time JSON → a static demo page
├── registry.json                 ← machine list the scraper reads
├── directory.json                ← full public directory (powers site "call to book")
├── schema.sql                    ← the database table definitions
├── scraper/                      ← the scraping engine (Python)  → scraper/README.md
├── worker/                       ← the read API (Cloudflare Worker) → worker/README.md
├── frontend/                     ← scripts embedded in the Squarespace site
├── .github/workflows/            ← the scheduled jobs → .github/workflows/README.md
├── scripts/                      ← one-off diagnostics → scripts/README.md
├── probe-results/                ← saved outputs of those diagnostics (artifacts)
├── local/                        ← local dev / status helpers
└── demo/                         ← the static demo page template + output
```

## Top level — data prep & data files

| File | What it is |
|---|---|
| `build_registry.py` | Reads all six `*_golf_courses_booking.csv`, regex-extracts each platform's IDs from the booking URLs, writes **`registry.json`**. Run after editing a CSV. |
| `build_directory.py` | Reads the same CSVs, emits one entry per course (bookable or not) tagged with how to book → **`directory.json`** (+ `worker/directory.gen.js`). |
| `build_demo.py` | Injects an aggregated tee-time JSON into `demo/template.html` → `demo/index.html`. |
| `registry.json` | Machine registry of scrapable courses + their platform IDs. Input to the scraper. |
| `directory.json` | Every course incl. phone-only/private; powers the site's directory. |
| `courses.csv` | Original master course list (name, city, website, platform). |
| `{colorado,arizona,florida,virginia,maryland,utah}_golf_courses_booking.csv` | Per-state source-of-truth sheets (course, booking platform, booking URL, confidence). The build scripts consume these. |
| `schema.sql` | D1 database schema (see `worker/README.md` for the tables). |
| `research_results.json` | Accumulated research/enrichment data (artifact). |

## `scraper/` — the scraping engine

Full detail in **`scraper/README.md`**. The core pipeline modules:

| File | What it does |
|---|---|
| `aggregate.py` | **The conductor.** For a date, runs the right adapter per registry course, collects results → one JSON doc. Main CLI. |
| `d1.py` | Syncs that JSON into the Cloudflare D1 database (insert new / update changed / deactivate gone); stamps the freshness ledger; prunes past slots. |
| `dates.py` | Computes which calendar dates to scrape (time-zone aware — "today" differs by zone). |
| `models.py` | The `TeeTime` and `FetchResult` data shapes everything is normalized into. |
| `sharding.py` | Splits the course list into N slices for parallel CI jobs. |
| `onetee.py` | Optional client to POST/CSV-export results to a future ingest API. |
| `gen_sample.py` | Generates fake tee-time data (same schema) for demo/dev. |
| `adapters/` | One module per booking platform → `scraper/adapters/README.md`. |
| `browser_*.py` | Browser-driven fetchers for platforms that block plain requests (clubcaddie, cps, ezlinks, golfnow, teeitup, tenfore, totale, trutee, supersaas, golfwithaccess). |
| `probe_*.py` | Read-only experiments used to work out how to reach a hard platform (no DB writes). |

---

## `scraper/adapters/` — one file per platform

Full table in **`scraper/adapters/README.md`**. `base.py` defines the shared
`Adapter` interface (`fetch(course, date) -> [TeeTime]`) and HTTP session. The
other 22 files each target one real booking platform (foreup, teeitup, chronogolf,
clubprophet, teesnap, clubcaddie, ezlinks, membersports, rguest, golfpay, golfrev,
courseco, quick18, foretees, golfback, tenfore, resortsuite, clubessential,
teequest, easytee, golfwithaccess, plus stubs in `experimental.py`).

## `worker/` — the read API

Full detail in **`worker/README.md`**.

| File | What it is |
|---|---|
| `index.js` | The Cloudflare Worker: serves `/api/health`, `/api/courses`, `/api/tee-times`, `/api/directory`, `/api/revalidate`; applies the freshness guard; prunes elapsed slots on a 5-min cron. |
| `wrangler.toml` | Worker config (D1 binding, cron triggers). |
| `directory.gen.js` | Generated by `build_directory.py`; the bundled directory the API serves. |
| `revalidate-ids.gen.js` | Generated map of `venue_id → platform IDs` for live click-time re-checks. |
| `../worker-cpsprobe/` | A separate one-off probe Worker (investigation artifact, not the live API). |

---

## `frontend/` — embedded in the Squarespace site

| File | What it is |
|---|---|
| `directory-cards.js` | Renders greyed "book by phone / private" cards beneath the live results, so missing courses show *how* to book rather than vanishing. |
| `state-filter.js` | Reads each course's `state` from the API and builds the state dropdown from whatever states are actually present. |

---

## `.github/workflows/` — the scheduled jobs (73 files)

Full grouping in **`.github/workflows/README.md`**. Three buckets:

- **~17 production scrapers** — the recurring near/mid/far tiers and per-platform
  browser scrapers that keep the site fresh.
- **~11 maintenance/deploy** — deploy the Worker, prune past slots, monitor health,
  rebuild registry/directory, watchdog the loops.
- **~45 probes/diagnostics** — throwaway investigation runs (safe to ignore for
  day-to-day work).

## `scripts/`, `probe-results/`, `local/`, `demo/`

| Folder | What it is |
|---|---|
| `scripts/` | ~49 one-off diagnostic / verification / data-fix utilities from development. A few are reusable tools (`monitor_inventory.py`, `state_status.py`, `enrich_phones.py`, `probe_staleness.py`); most `diag_*` are frozen bug-hunt snapshots. See `scripts/README.md`. |
| `probe-results/` | Saved text/JSON outputs of those scripts and probe workflows — investigation artifacts, not part of the running pipeline. |
| `local/` | Local dev/status helpers: PowerShell setup scripts, an env template, phone data, and generated status snapshots. |
| `demo/` | `template.html` + generated `index.html` — a self-contained demo of the search UI. |
| `patches/`, `*.patch` | A saved bugfix patch bundle from an earlier batch of fixes. |
